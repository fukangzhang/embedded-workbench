# 目标
建立第一版 FreeRTOS 任务创建骨架，让 `rtos_port_start()` 在 FreeRTOS 构建下能够创建任务模型中定义的任务。

## 范围
- 在 `rtos_port_freertos` 中接入 `xTaskCreate`
- 为传感器采集、环境处理、通信、告警输出四个任务提供最小任务函数
- 保存任务 handle，避免重复创建
- 固件 FreeRTOS 自检覆盖任务创建路径
- 补充学习笔记

## 暂不做
- 不调用 `vTaskStartScheduler`
- 不接真实传感器驱动
- 不接真实 UART/命令输入
- 不处理任务删除和重启
- 不做板上运行验证

## 步骤
1. 扩展 FreeRTOS port 上下文，保存四个任务 handle
2. 新增四个最小任务函数
3. 将 `rtos_port_start()` 映射到任务创建流程
4. 保持队列收发自检可构建
5. 运行 host 测试、普通 firmware 构建、FreeRTOS firmware 构建
6. 更新学习文档并归档计划

## 验证方式
- 主机：`cmake --build build --target test`
- 固件无 RTOS：`cmake --build build-fw`
- 固件带 RTOS：`cmake --build build-fw-rtos --clean-first`
- GitHub Actions：主机、固件、FreeRTOS 固件 job 通过

## 未决问题
- `vTaskStartScheduler()` 的真正接入仍需单独做，因为它正常情况下不会返回
- 任务函数目前只保留最小数据流骨架，后续再接真实采集、处理、通信和输出逻辑
