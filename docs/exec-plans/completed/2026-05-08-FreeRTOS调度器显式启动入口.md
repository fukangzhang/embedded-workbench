# 目标
建立 FreeRTOS 调度器显式启动入口，让固件可以通过构建开关选择是否在任务创建后调用 `vTaskStartScheduler()`。

## 范围
- 新增 `EW_FREERTOS_START_SCHEDULER` CMake 开关，默认关闭
- 在 FreeRTOS port 中提供显式 scheduler handoff 函数
- firmware 仅在开关打开时调用 scheduler handoff
- 保持默认 CI 仍做构建级验证，不声称板上调度已验证
- 补充学习笔记

## 暂不做
- 不默认启动调度器
- 不做板上运行验证
- 不调整 startup/vector table
- 不接真实 SysTick/PendSV/SVC 调试记录
- 不把任务函数推进到完整业务实现

## 步骤
1. 新增 CMake 开关和固件编译宏
2. 新增 FreeRTOS scheduler handoff API
3. firmware 在显式开关打开时调用 handoff
4. 运行 host 测试、普通 firmware 构建、FreeRTOS firmware 构建
5. 增加 scheduler 开关打开的链接级构建验证
6. 更新学习文档并归档计划

## 验证方式
- 主机：`cmake --build build --target test`
- 固件无 RTOS：`cmake --build build-fw`
- 固件带 RTOS：`cmake --build build-fw-rtos --clean-first`
- 固件带 RTOS 且 scheduler 开关打开：`cmake --build build-fw-scheduler --clean-first`
- GitHub Actions：主机、固件、FreeRTOS 固件 job 通过

## 未决问题
- scheduler 真正运行需要板上验证，后续要记录 SysTick/PendSV/SVC、时钟和中断优先级行为
- 当前开关打开只证明固件能链接到 `vTaskStartScheduler()` 路径，不代表任务已经在真实硬件上调度运行
