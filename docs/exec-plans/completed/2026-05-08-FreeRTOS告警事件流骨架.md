# 目标
把 FreeRTOS 任务模型中的 `alarm_event_queue` 接入真实 FreeRTOS port，让环境处理任务可以把告警事件发送给告警输出任务。

## 范围
- 扩展 FreeRTOS port context，保存 `alarm_event_queue`
- 初始化 `RTOS_QUEUE_ALARM_EVENT`
- 环境处理任务在更新告警状态后发送告警事件
- 告警输出任务阻塞接收告警事件
- 补充学习笔记

## 暂不做
- 不接真实 LED、蜂鸣器或执行器
- 不改变公共 `rtos_port` 接口
- 不启动板上运行验证
- 不实现完整任务业务闭环

## 步骤
1. 新增 FreeRTOS 告警事件消息结构
2. 扩展 FreeRTOS context 和 queue 初始化
3. `env_process_task` 发送告警事件
4. `alarm_output_task` 接收告警事件
5. 运行 host、普通 firmware、FreeRTOS firmware、scheduler firmware 构建验证
6. 更新学习文档并归档计划

## 验证方式
- 主机：`cmake --build build --target test`
- 固件无 RTOS：`cmake --build build-fw`
- 固件带 RTOS：`cmake --build build-fw-rtos --clean-first`
- 固件带 RTOS 且 scheduler 开关打开：`cmake --build build-fw-scheduler --clean-first`
- GitHub Actions：主机、固件、FreeRTOS 固件 job 通过

## 未决问题
- 告警输出任务目前只消费事件，不驱动真实硬件
- 后续需要把事件内容映射到 LED、蜂鸣器或其他执行器策略
