# FreeRTOS 内核接入预研

## 这一阶段在做什么？
前面已经有 RTOS 适配接口，但还没有真正链接 FreeRTOS 内核。

这一阶段做的是第一版真实 FreeRTOS-Kernel 外部接入骨架：

- 新增 `firmware/config/FreeRTOSConfig.h`
- 新增 `cmake/FreeRTOSKernel.cmake`
- 新增 `EW_USE_FREERTOS` 构建开关
- 固件目标可以选择链接外部 FreeRTOS-Kernel
- CI 可以 clone 官方 FreeRTOS-Kernel 并验证 ELF 构建

注意：这一步还没有创建真实任务，也没有启动调度器。

## 为什么不把 FreeRTOS 源码复制进仓库？
FreeRTOS-Kernel 是第三方源码。直接复制进项目会带来几个问题：

- 仓库变大
- 版本来源不清楚
- 后续升级困难
- 需要更仔细处理 license 和来源记录

所以当前采用外部路径：

```cmake
FREERTOS_KERNEL_PATH
```

本地可以指向自己 clone 的 FreeRTOS-Kernel，CI 里临时 clone 官方仓库。

## FreeRTOSConfig.h 是什么？
`FreeRTOSConfig.h` 是应用项目提供给 FreeRTOS 的配置文件。

它决定：

- 是否抢占式调度
- tick 频率
- 最大优先级数量
- heap 大小
- 是否启用 timer
- 中断优先级配置
- 哪些 API 可用

它不是 FreeRTOS-Kernel 自带的固定文件，而是每个项目根据 MCU 和需求自己定义。

## 为什么默认使用 GCC_ARM_CM3 port？
目标板是 Cortex-M4F，但当前使用 Zig freestanding 作为临时验证工具链。FreeRTOS 的 `GCC/ARM_CM4F` port 包含 FPU 上下文保存相关汇编，对当前 Zig 路径不够友好。

为了先验证 FreeRTOS-Kernel 源码、配置头、heap 和固件链接路径，当前默认使用：

```cmake
FREERTOS_PORT=GCC_ARM_CM3
```

这个选择适合“先不启用 FPU 上下文保存”的 Cortex-M4 初期构建验证。

后续使用真实 ARM GNU Toolchain 和板上验证时，可以切换到：

```cmake
FREERTOS_PORT=GCC_ARM_CM4F
```

## 为什么需要 freestanding libc 兼容层？
FreeRTOS-Kernel 会包含一些标准头，例如：

- `stdlib.h`
- `string.h`

真实 ARM GNU Toolchain 通常会通过 newlib 提供这些头和基础函数。

当前 Zig freestanding 环境没有完整 C 库，所以项目补了一个很小的兼容层：

- `firmware/libc/include/stdlib.h`
- `firmware/libc/include/string.h`
- `firmware/libc/src/memory.c`

它只提供当前构建需要的最小内容，例如 `memcpy`、`memset`、`memmove`。

## 为什么不能把这个 libc 传给 host 构建？
主机测试和 host simulation 运行在普通操作系统上，本来应该使用系统自己的 C 标准库。

如果把 `firmware/libc/include` 通过 `embedded_app` 这类公共库传播给 host 目标，主机编译器会优先看到项目里的简化版 `string.h`。这个文件只声明了固件当前需要的少量函数，没有声明 `strcmp` 等系统函数，主机测试就会编译失败。

所以当前做法是：

- `embedded_app` 不依赖 freestanding libc
- 普通业务逻辑和 host 测试继续使用系统 C 库
- `embedded_firmware` 和 `freertos_kernel` 单独链接 `embedded_freestanding_support`

这也是嵌入式项目里常见的隔离思路：业务逻辑尽量保持平台无关，硬件和工具链相关内容只在目标固件那一侧接入。

## 当前 CI 验证了什么？
现在 CI 有三条线：

- 主机 CMake 测试
- 普通 firmware ELF 构建
- 链接 FreeRTOS-Kernel 的 firmware ELF 构建

这证明：

- 业务逻辑测试没坏
- 固件骨架能链接
- FreeRTOS-Kernel 外部接入路径能编译和链接

## 后续还缺什么？
下一步才是真正的 RTOS 运行时接入：

- 创建真实任务
- 创建真实队列
- 用 FreeRTOS port 实现 `rtos_port`
- 调用 `vTaskStartScheduler`
- 处理 SysTick/PendSV/SVC
- 在板上验证任务调度

当前阶段只完成“内核能被接入和链接”的前置条件。
