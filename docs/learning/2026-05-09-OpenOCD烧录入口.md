# OpenOCD 烧录入口

## 这一步做了什么？

项目新增了一个脚本：

```text
scripts/flash_nucleo_f401re_openocd.ps1
```

它的作用是把前面生成的固件镜像交给 OpenOCD，用 NUCLEO-F401RE 板载 ST-LINK 下载到 STM32F401RE。

## 对应代码

- `scripts/flash_nucleo_f401re_openocd.ps1`
- `hardware/nucleo-f401re-bringup.md`
- `docs/design-docs/2026-05-09-OpenOCD烧录入口边界.md`

## 为什么用 OpenOCD 的 program？

OpenOCD 有很多底层 flash 命令。对初学者来说，直接写 `flash write_image`、`verify_image`、`reset` 容易把顺序弄乱。

OpenOCD 官方文档提供了一个更高层的 `program` helper。它会处理初始化、复位到烧录状态、写入镜像、可选校验、可选复位和退出。项目脚本使用的核心命令类似：

```text
program firmware.elf verify reset exit
```

## ELF、HEX、BIN 怎么选？

优先用：

```text
embedded_firmware.elf
```

原因是 ELF 自带地址和段信息，OpenOCD 能知道哪些内容应该写到哪里。

`embedded_firmware.hex` 也带地址信息，通常也可以直接烧录。

`embedded_firmware.bin` 是裸二进制，不自带 flash 地址。因此脚本在发现 `.bin` 时会自动补上 STM32F401RE 内部 flash 起始地址：

```text
0x08000000
```

对应的 OpenOCD 命令形状是：

```text
program firmware.bin verify reset exit 0x08000000
```

## 先 dry-run

第一次不要直接烧录，先看脚本会执行什么：

```powershell
.\scripts\flash_nucleo_f401re_openocd.ps1 -DryRun
```

你会看到最终 OpenOCD 命令，但它不会真正连接板子。

## 真实烧录前要确认什么？

1. 已连接 NUCLEO-F401RE 的 ST-LINK USB 口。
2. OpenOCD 已安装，并且 `openocd` 在 PATH 中，或者通过 `-OpenOcd` 指定完整路径。
3. 固件已经构建，默认镜像存在：

```text
build-fw-real-usart2-command/embedded_firmware.elf
```

## 这一步还没证明什么？

脚本和文档只能证明“烧录命令入口已经准备好”。没有真实板卡连接和串口/调试器观察之前，仍然不能说固件已经在硬件上跑通。
