# Windows C 工具链准备

## 为什么现在卡在工具链？
这个项目使用 `CMake` 描述构建流程，但 `CMake` 本身不编译代码。它需要配合一个真正的 C 编译器，例如：

- MSVC：Visual Studio 或 Build Tools 提供
- GCC：MinGW 或 MSYS2 提供
- Clang：LLVM 提供

最初当前环境里暂时没有找到：

- `cmake`
- `gcc`
- `clang`
- `cl`

所以一开始只能写代码和文档，不能完成真正的编译验证。

## 本项目当前采用的临时验证方式
为了先把项目推进起来，当前使用用户目录下的 Python venv 安装了：

- `cmake`
- `ninja`
- `ziglang`

其中 `ziglang` 提供 `zig cc`，可以作为主机侧 C 编译器使用。

当前验证命令使用的是 venv 里的工具，而不是全局 PATH 里的工具。

## 推荐安装路线
为了后续同时兼顾嵌入式和主机测试，推荐优先使用：

1. CMake
2. Ninja
3. ARM GNU Toolchain
4. 一个主机 C 编译器

在 Windows 上比较稳的路线是安装 Visual Studio Build Tools，并勾选 C++ 桌面开发工具链。虽然我们主要写 `C`，但 MSVC 的 C 编译器随这个工具链提供。

也可以使用 MSYS2 或 MinGW，但后续接 STM32 时仍然需要单独安装 ARM 工具链。

## 后续验证命令
如果以后把 CMake 和编译器加入全局 PATH，回到项目根目录运行：

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

如果这些命令都通过，说明主机侧工程骨架已经闭环。

如果继续使用当前 venv 工具链，可以用下面这种形式：

```powershell
& 'C:\Users\fukan\.codex\venvs\embedded-workbench-toolchain\Scripts\cmake.exe' -S . -B build -G Ninja `
  -D CMAKE_MAKE_PROGRAM='C:\Users\fukan\.codex\venvs\embedded-workbench-toolchain\Scripts\ninja.exe' `
  -D CMAKE_C_COMPILER='C:\Users\fukan\.codex\venvs\embedded-workbench-toolchain\Lib\site-packages\ziglang\zig.exe' `
  -D CMAKE_C_COMPILER_ARG1=cc `
  -D CMAKE_AR='C:\Users\fukan\.codex\venvs\embedded-workbench-toolchain\Scripts\zig-ar.cmd' `
  -D CMAKE_RANLIB='C:\Users\fukan\.codex\venvs\embedded-workbench-toolchain\Scripts\zig-ranlib.cmd'

& 'C:\Users\fukan\.codex\venvs\embedded-workbench-toolchain\Scripts\cmake.exe' --build build
& 'C:\Users\fukan\.codex\venvs\embedded-workbench-toolchain\Scripts\ctest.exe' --test-dir build --output-on-failure
```
