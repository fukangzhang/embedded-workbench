# C代码注释阅读方法

## 这一步为什么要做？

你现在不熟 C，也不熟嵌入式。如果只看代码，很容易同时被三类东西绊住：

- C 语言写法，比如指针、结构体、`static`、`volatile`、字符串结尾 `'\0'`
- 嵌入式概念，比如 GPIO 寄存器、RCC 时钟、FreeRTOS 队列和任务句柄
- 项目架构，比如为什么 `app` 不直接操作 GPIO，为什么测试不能解引用 STM32 真实地址

所以本项目的代码注释采用一个原则：普通结构简单提示，关键逻辑和容易误解的边界详细解释。

## 代码注释应该怎么看？

建议按下面顺序读一个模块：

1. 先看头文件 `*.h`

   头文件告诉你“这个模块对外承诺什么”。比如 `stm32_gpio_config.h` 里注释会解释 `volatile` 寄存器结构体、端口名和寄存器地址表的关系。

2. 再看源文件 `*.c`

   源文件告诉你“这个模块内部怎么做”。比如 `command_parser.c` 里注释会解释 `cursor` 指针为什么不断向后移动，以及为什么手写整数解析。

3. 最后看测试 `tests/test_*.c`

   测试告诉你“哪些行为已经被固定”。比如 `test_stm32f401re_gpio_bindings.c` 只比较地址数值，不解引用真实 STM32 地址。

## 看完以后你应该能解释什么？

你不需要马上记住所有 C 语法，但应该能用自己的话解释：

- 为什么 `config == 0` 代表空指针检查
- 为什么字符串用 `'\0'` 表示结束
- 为什么 `volatile uint32_t *` 常用于硬件寄存器地址
- 为什么主机测试不能直接访问 `0x40020000` 这类 STM32 地址
- 为什么状态机里进入 `ALARM` 用任一条件，恢复用全部条件
- 为什么 FreeRTOS 的队列和任务句柄集中放在 context 里

## 后续怎么继续补？

后面每做一个新模块，都按同一标准处理：

- 对外接口：解释模块边界和调用者该知道什么
- 核心逻辑：解释关键判断、指针移动、位运算、状态流转
- 硬件边界：解释哪些代码可在主机测试，哪些只能在目标板运行
- 测试文件：解释测试为什么这样验证，以及没有覆盖什么
