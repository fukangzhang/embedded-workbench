# STM32 板级 USART2 初始化

## 这一步做了什么？

这一步新增了 `stm32_board_usart2_init`，把前面分散完成的 USART2 相关模块串成一条可测试的初始化链路：

```text
打开 GPIOA 时钟
  -> 把 PA2/PA3 切到 AF7
  -> 打开 USART2 时钟
  -> 配置 USART2 为 9600 8N1
```

这里的“板级”意思是：它已经知道当前目标板使用 STM32F401RE、USART2、PA2/PA3、AF7。它不是纯通用 driver，也还不是完整业务应用。

## 为什么顺序重要？

STM32 外设通常不能只写一个寄存器就工作。USART2 至少需要三类条件同时满足：

- GPIO 端口时钟打开，否则 PA2/PA3 的 GPIO 配置不可靠。
- PA2/PA3 切到 alternate function AF7，否则引脚还没有连接到 USART2。
- USART2 外设时钟打开，否则 USART2 自己的寄存器配置不会产生有效外设行为。

所以初始化顺序不是随便排的。先准备引脚，再准备外设，最后打开 USART 的收发功能，更容易定位问题。

## 代码怎么读？

建议按这个顺序：

1. `drivers/include/embedded_workbench/stm32_board_usart2_init.h`
   - 先看函数参数。
   - 理解为什么它接收 `gpio_clock_context`、`gpio_context`、`usart_clock_context`、`usart_registers` 和 `usart_config`。

2. `drivers/src/stm32_board_usart2_init.c`
   - 看 `stm32f401re_usart2_tx_pin()` 和 `stm32f401re_usart2_rx_pin()`。
   - 看 `STM32F401RE_USART2_GPIO_AF` 如何变成 GPIO alternate function 配置。
   - 看最后一段 `&&` 链：每一步成功才进入下一步。

3. `tests/test_stm32_board_usart2_init.c`
   - 看 `ahb1enr`、`apb1enr`、`gpioa`、`usart2` 这些假寄存器。
   - 看测试如何检查 bit0、bit17、PA2/PA3 的 `MODER/AFRL` 和 USART2 的 `BRR/CR1`。
   - 记住：主机测试验证的是“我们会写对哪些位”，不是证明真实板子已经发出串口波形。

## 关键 C 知识

这一步会遇到几个 C 语言点：

- `const xxx *`：表示函数只读取这个对象，不应该修改它。
- `volatile uint32_t`：用来模拟硬件寄存器这种“值可能被硬件改变”的内存位置。
- `&&` 短路：前一步返回 `false`，后一步就不会执行。
- 位运算：GPIO mode、AF、RCC enable 都是通过设置寄存器里的某几位完成的。

## 和前面模块怎么对应？

可以这样记：

```text
stm32f401re_gpio_bindings
  提供 PA2/PA3/AF7/USART2 bit17 这些事实

stm32_rcc_gpio_clock
  负责打开 GPIOA 时钟

stm32_gpio_config
  负责把 PA2/PA3 设置成 AF7

stm32_rcc_usart_clock
  负责打开 USART2 时钟

stm32_usart
  负责写 BRR/CR1，配置 8N1 和收发开关

stm32_board_usart2_init
  负责按板级顺序把它们串起来
```

## 面试时怎么讲？

可以说：

> 我把 STM32 串口初始化拆成可测试的小模块：RCC、GPIO AF、USART 寄存器和芯片绑定分开实现，最后用板级 init 串起来。这样硬件相关地址集中在 binding 层，通用 driver 可以在主机上用假寄存器测试，避免所有验证都依赖真实板卡。

这个表达能体现你理解了嵌入式项目里“硬件事实、寄存器操作、业务逻辑”三者要分层。
