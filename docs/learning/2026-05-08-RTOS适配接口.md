# RTOS 适配接口

## 为什么需要 RTOS 适配接口？
如果应用层到处直接调用 FreeRTOS API，例如：

```c
xQueueSend(...)
xQueueReceive(...)
xTaskCreate(...)
```

那么主机测试就很难跑，因为主机环境没有真正的 FreeRTOS 调度器。

所以这一阶段先定义 `rtos_port`，让应用层只依赖一组小接口：

- 启动任务系统
- 发送传感器样本
- 发送命令
- 接收响应

底层可以是：

- 主机 fake 实现
- 未来 FreeRTOS 实现
- 其他 RTOS 实现

## 操作表是什么？
当前接口使用操作表：

```c
typedef struct {
    bool (*start)(void *context);
    bool (*send_sensor_sample)(void *context, const sensor_sample_t *sample);
    bool (*send_command)(void *context, const command_t *command);
    bool (*receive_response)(void *context, rtos_response_message_t *response);
} rtos_port_ops_t;
```

这是一种 C 语言里常见的接口抽象方式。它有点像面向对象里的接口，但完全用 C 函数指针实现。

## 为什么现在不直接引入 FreeRTOS？
真实 FreeRTOS 接入需要：

- FreeRTOS-Kernel 源码
- FreeRTOSConfig.h
- heap 实现
- Cortex-M port
- 中断优先级配置
- 任务创建和队列创建

这些会让改动变大，也更依赖目标板工程。

现在先把边界定好，后续写 FreeRTOS port 时，只需要实现这组操作表。

## 当前测试覆盖
当前测试使用主机 fake port，覆盖：

- port 合法性检查
- start 调用
- 发送有效传感器样本
- 拒绝无效传感器样本
- 发送有效命令
- 拒绝无效命令
- 接收响应
- 空 port 失败路径

这证明了接口行为本身可以在没有 RTOS 的情况下验证。
