# 序列传感器来源

## 这一步做了什么？

项目新增了一个模拟传感器来源：

```text
sequence_sensor_source
```

它会按照数组顺序一帧一帧吐出 `sensor_sample_t`。这让主机仿真不再直接遍历裸数组，而是走和后续真实传感器一致的接口：

```text
sensor_source_read
```

## 对应代码

- `drivers/include/embedded_workbench/sequence_sensor_source.h`
- `drivers/src/sequence_sensor_source.c`
- `tests/test_sequence_sensor_source.c`
- `tools/host_sim/main.c`

## 为什么要做这个？

上一阶段有了 `sensor_source_t`，但它只是接口。为了证明这个接口确实能承载一种来源，需要先实现一个最简单、最可控的来源：预设样本序列。

这对学习很有用，因为你可以看到同一条数据线：

```text
sequence_sensor_source
  -> sensor_source_read
  -> sensor_sample_t
  -> alarm_state_update
  -> alarm_output
```

后续真实传感器接入时，只需要换掉 source 实现，后面的状态机和输出策略不用重写。

## 它怎么工作？

初始化时传入：

- sample 数组
- sample 数量
- 是否重复最后一帧

读取时：

1. 如果还有下一帧，返回当前帧并把 index 往后移。
2. 如果已经读完且 `repeat_last=false`，返回失败。
3. 如果已经读完且 `repeat_last=true`，继续返回最后一帧。

## 为什么样本数组不复制？

`sequence_sensor_source_t` 只保存数组指针和数量，不复制整段数组。

这样更接近嵌入式写法：调用者可以把样本表放在静态存储区，source 只负责按索引读取，不需要动态内存。

## host_sim 有什么变化？

`host_sim` demo 仍然展示同一组 normal/warning/alarm/recovery 样本，但内部读取方式变成：

```text
sequence_sensor_source_as_source
  -> sensor_source_read
```

这说明主机仿真也在逐步靠近真实采集架构，而不是只做一次性演示代码。

## 这还不是硬件传感器

sequence source 是仿真和测试工具。它不访问 I2C、SPI 或 ADC，也不代表真实传感器已经接入。

真正的硬件接入会在后续 source 实现里完成。
