# 固件真实 USART2 命令 Loop 开关

## 这一步做了什么？

这一步新增一个默认关闭的固件构建开关：

```text
EW_FIRMWARE_USE_REAL_STM32_USART2_COMMAND_LOOP
```

打开后，固件会用真实 STM32F401RE 地址初始化 USART2，并在 `while (1)` 中轮询命令链路：

```text
USART2 RXNE/DR
  -> stm32_usart_serial_io_read_byte
  -> serial_command_pump_poll
  -> serial_command_service
  -> stm32_usart_serial_io_write
  -> USART2 TXE/DR
```

## 为什么默认关闭？

因为这个路径会解引用真实 STM32 外设地址，比如 RCC、GPIOA 和 USART2。它只能在真正跑在 NUCLEO-F401RE 上时才有意义。

默认固件和主机测试不能直接运行这条真实地址路径，所以项目用编译开关保护它：

- 默认构建：只做安全自检。
- 打开开关：用于真实板卡 bring-up。
- CI：只验证打开开关后能编译链接，不证明板上串口交互。

## 代码怎么读？

建议按这个顺序：

1. `CMakeLists.txt`
   - 看 `EW_FIRMWARE_USE_REAL_STM32_USART2_COMMAND_LOOP`。
   - 看它如何变成 `EW_FIRMWARE_USE_REAL_STM32_USART2_COMMAND_LOOP=1` 编译宏。

2. `firmware/src/main.c`
   - 看 `firmware_stm32f401re_real_usart2_command_loop_init`。
   - 看它如何初始化 USART2、I/O adapter 和 `serial_command_service`。
   - 看 `while (1)` 中如何调用 `firmware_stm32f401re_real_usart2_command_loop_poll`。

3. `.github/workflows/ci.yml`
   - 看新增的 `build-fw-real-usart2-command`。
   - 记住 CI 只做构建，不做板上运行。

## 板上怎么验证？

后续真实验证应使用 NUCLEO-F401RE 的 ST-LINK VCP，串口参数先按当前配置：

```text
baud: 9600
data bits: 8
parity: none
stop bits: 1
line ending: LF or CRLF
```

输入：

```text
STATUS?
```

预期看到以 `OK result=ok` 开头的响应。

## 面试时怎么讲？

可以说：

> 我把真实 USART2 命令 loop 做成默认关闭的固件开关。默认构建仍然安全，打开开关后才解引用 STM32F401RE 的真实 RCC/GPIO/USART2 地址。CI 会验证这条硬件路径能编译链接，真实串口交互再通过板卡 bring-up 清单记录。
