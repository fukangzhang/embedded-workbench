# 串口行缓冲模块

## 这一阶段在做什么？

串口通信不是一次收到完整字符串，而是一个字节一个字节到达。比如用户在终端里输入：

```text
STATUS?
```

底层 UART 看到的是：

```text
'S' -> 'T' -> 'A' -> 'T' -> 'U' -> 'S' -> '?' -> '\r' -> '\n'
```

本阶段新增 `serial_line` 模块，负责把这些字节攒成一行完整命令，再交给已有的 `command_parser`。

## 对应代码

- `drivers/include/embedded_workbench/serial_line.h`
- `drivers/src/serial_line.c`
- `tests/test_serial_line.c`
- `CMakeLists.txt`

## 为什么放在 drivers？

`serial_line` 不知道告警状态机，也不处理配置命令。它只关心“字节流如何变成一行文本”，这是通信输入的通用驱动辅助逻辑，所以放在 `drivers/`。

未来接入真实 USART2 时，链路会变成：

```text
USART2 RX byte
  -> serial_line
  -> command_parser
  -> command_handler
  -> response_format
  -> USART2 TX byte
```

## 关键规则

- 普通字符进入内部缓冲区。
- `\n` 或 `\r` 表示一行结束。
- 空行会被忽略，不交给命令解析器。
- `\r\n` 只应该产生一行，不应该多产生一个空命令。
- 缓冲区满时返回 `SERIAL_LINE_STATUS_OVERFLOW` 并复位，避免残缺命令继续污染后续输入。

## 代码怎么读？

先看 `serial_line.h`：

- `serial_line_reader_t` 保存内部缓冲区、容量、当前长度。
- 缓冲区由调用者传入，模块不分配内存。
- `serial_line_feed` 每次只喂 1 个字节。

再看 `serial_line.c`：

- `serial_line_reader_init` 初始化状态。
- `complete_line` 在遇到换行时复制完整行到 `line_out`。
- `serial_line_feed` 决定当前字节是普通字符、换行、溢出还是错误。

最后看 `tests/test_serial_line.c`：

- 验证 `\n` 完成一行。
- 验证 `\r\n` 不产生重复命令。
- 验证空行忽略。
- 验证溢出后能复位并继续使用。

## 看完以后你应该能解释什么？

- 为什么 UART 需要“行缓冲”而不是直接调用 `command_parse`。
- 为什么嵌入式里常让调用者提供缓冲区。
- 为什么内部缓冲和输出缓冲都要给 `'\0'` 留位置。
- 为什么溢出后选择复位，而不是把截断的命令交给 parser。
