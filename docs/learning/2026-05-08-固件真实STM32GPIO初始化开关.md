# 固件真实STM32GPIO初始化开关

## 这一阶段在做什么？

前面已经完成了两类能力：

- 用模拟寄存器验证 GPIO 初始化链路
- 用 `stm32f401re_gpio_bindings` 保存 STM32F401RE 的真实 RCC/GPIO 地址

本阶段把这两者接起来：新增 `EW_FIRMWARE_USE_REAL_STM32_GPIO_INIT` 编译开关。打开后，固件会使用 STM32F401RE 的真实地址绑定去执行告警输出 GPIO 初始化。

默认情况下这个开关是关闭的。

## 对应代码

- `CMakeLists.txt`
- `.github/workflows/ci.yml`
- `firmware/src/main.c`
- `drivers/include/embedded_workbench/stm32f401re_gpio_bindings.h`
- `drivers/src/stm32f401re_gpio_bindings.c`

## 为什么要做成开关？

真实 GPIO 初始化会解引用这些地址：

```text
RCC_AHB1ENR: 0x40023830
GPIOA:       0x40020000
GPIOB:       0x40020400
```

这些地址只有在 STM32F401RE 芯片上才是有效硬件寄存器。在普通电脑上访问它们会崩溃；在 CI 里也不能运行这段逻辑。

所以开关的意义是：

- 默认固件继续用模拟寄存器做安全自检
- 打开开关时，目标板固件会编译进真实初始化路径
- CI 只构建 ELF，确认代码能编译链接，不运行真实寄存器访问

## 代码怎么读？

先看 `CMakeLists.txt`：

- `EW_FIRMWARE_USE_REAL_STM32_GPIO_INIT` 默认 `OFF`
- 开关打开时给 `embedded_firmware` 加编译宏

再看 `firmware/src/main.c`：

- 默认总是运行 `firmware_stm32_gpio_init_self_check`
- 开关打开时额外运行 `firmware_stm32f401re_real_gpio_init`
- 真实路径从 `stm32f401re_gpio_bindings` 取 RCC/GPIO 表，再调用 `stm32_board_gpio_init_alarm_outputs`

最后看 CI：

- 普通固件构建仍然存在
- 额外新增一次 `build-fw-real-gpio` 构建，用来防止真实路径腐烂

## 这一步证明了什么？

它证明：

- 固件可以选择编译真实 STM32F401RE GPIO 初始化路径
- 真实地址绑定和已有 GPIO 初始化模块能接起来
- 该路径能通过目标固件 ELF 构建

## 这一步还不能证明什么？

它还不能证明：

- 板上 LED 已经亮
- 蜂鸣器或执行器已经动作
- 引脚电平、电气连接和外设供电都正确

这些必须通过后续板上下载、示波器/万用表/实际现象观察来验证。
