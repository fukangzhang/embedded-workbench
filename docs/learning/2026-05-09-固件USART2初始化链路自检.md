# 固件 USART2 初始化链路自检

## 这一阶段在做什么？

前面已经完成了板级 USART2 初始化：

```text
stm32_board_usart2_init
  -> GPIOA clock
  -> PA2/PA3 AF7
  -> USART2 APB1 clock
  -> USART2 8N1 config
```

这一阶段把它接进 `firmware/src/main.c` 的固件自检。也就是说，固件入口现在会调用一次 USART2 初始化链路，并检查模拟寄存器是否被写成预期状态。

## 对应代码

- `firmware/src/main.c`
- `drivers/include/embedded_workbench/stm32_board_usart2_init.h`
- `drivers/src/stm32_board_usart2_init.c`
- `drivers/include/embedded_workbench/stm32f401re_gpio_bindings.h`

## 自检做了什么？

`firmware_stm32_usart2_init_self_check` 使用这些模拟寄存器：

```text
firmware_rcc_ahb1enr
firmware_rcc_apb1enr
firmware_gpioa_registers
firmware_usart2_registers
```

然后按这个流程执行：

```text
绑定 "PA" 到 GPIOA clock bit0
绑定 "PA" 到 GPIOA 模拟寄存器
使用 STM32F401RE 的 USART2 clock binding
调用 stm32_board_usart2_init
检查 GPIOA clock bit0
检查 USART2 APB1 clock bit17
检查 PA2/PA3 是 alternate mode
检查 PA2/PA3 是 AF7
检查 USART2 BRR 和 CR1
```

## 为什么还用模拟寄存器？

因为 CI 和本地构建不会真的跑在 STM32 板上。默认固件路径如果直接解引用 `0x40004400` 这种真实 USART2 地址，在主机或错误环境下没有意义，也不安全。

模拟寄存器能先证明：

- 固件入口已经引用 USART2 初始化链路。
- `stm32_board_usart2_init` 能在目标固件构建中链接成功。
- GPIO/RCC/USART 的寄存器写位符合我们预期。

它不能证明：

- NUCLEO-F401RE 的 USB-UART 已经收到数据。
- PA2/PA3 上已经出现真实串口波形。
- 串口命令服务已经能从真实 USART2 读字节。

## 代码怎么读？

建议你这样看：

1. 先看 `firmware/src/main.c` 顶部新增的模拟寄存器。
2. 再看 `gpio_pin_is_alternate` 和 `gpio_pin_has_alternate_function`，理解怎么从 `MODER/AFRL` 读回检查结果。
3. 再看 `firmware_stm32_usart2_init_self_check`，重点看它怎样初始化 context。
4. 最后看 `main` 里的总条件，确认 USART2 自检已经成为 `firmware_self_check = 1` 的必要条件之一。

## 面试时怎么讲？

可以说：

> 我没有一上来把真实串口地址塞进 main，而是先做了固件级 USART2 初始化自检。它用模拟寄存器验证 PA2/PA3 AF7、USART2 时钟和 8N1 配置都能在固件入口串起来，等这条链路稳定后再切到真实板卡和串口命令服务。
