# SAMPLE 命令

## 这一步做了什么？

项目新增了一条文本命令：

```text
SAMPLE <temp_c_x10> <humidity_rh_x10> <light_lux> <smoke_ppm>
```

例如：

```text
SAMPLE 360 600 250 20
```

这表示注入一帧传感器样本：

- 温度：`36.0 C`
- 湿度：`60.0 %RH`
- 光照：`250 lux`
- 烟雾：`20 ppm`

## 为什么需要它？

真实传感器还没接入前，如果 sample 永远固定，串口演示只能看到同一个状态。

有了 `SAMPLE`，你可以在 `host_sim` 或后续真实 USART2 命令 loop 里手动输入不同传感器值，观察：

```text
传感器样本 -> 告警状态 -> 输出策略
```

比如输入一个偏高温度后，系统会从 normal 进入 warning，并返回新的 `STATUS`。

## 它怎么流转？

```text
SAMPLE 360 600 250 20
  -> command_parser 读出 4 个整数
  -> command_handler 校验并写回 sensor_sample_t
  -> command_session 重新计算 alarm_state
  -> response_format_status 输出最新状态
```

成功响应类似：

```text
OK result=ok
STATUS state=warning temp_c_x10=360 humidity_rh_x10=600 light_lux=250 smoke_ppm=20 indicator=slow_blink buzzer=off actuator=off period_ms=1000
```

## 为什么 parser 不直接判断范围？

parser 只判断“文本语法是否正确”。例如 4 个字段是不是整数、有没有多余参数。

具体数值是否符合项目支持的传感器范围，由 `command_handler` 通过 `sensor_sample_is_valid` 判断。这样可以保持分层清楚：

- parser：文本到结构体。
- handler：结构体能不能改变系统状态。
- session：改变后怎么生成响应。

## 这不是传感器驱动

`SAMPLE` 是调试和演示入口，不代表真实传感器已经接入。

真实传感器驱动后续仍然需要解决：

- 传感器硬件接口，比如 I2C/SPI/ADC。
- 采样周期。
- 读取失败和异常值处理。
- FreeRTOS 采集任务如何把样本送进处理队列。
