# STM32 固件工程骨架

## 这一阶段在做什么？
前面已经能把核心库编译成 ARM 静态库。这一阶段进一步生成一个最小 `.elf` 固件文件。

当前固件骨架包括：

- 启动文件：`firmware/startup/startup_stm32f401re.c`
- 链接脚本：`firmware/linker/stm32f401re.ld`
- 固件入口：`firmware/src/main.c`
- CMake 固件目标：`embedded_firmware.elf`

这还不是可以直接拿去做完整产品的固件，但它已经具备 MCU 固件工程的基本形态。

## 启动文件负责什么？
普通主机程序由操作系统负责启动。MCU 上没有操作系统帮你做这些事，所以启动文件要负责：

1. 提供中断向量表
2. 设置复位入口 `Reset_Handler`
3. 把 `.data` 从 Flash 复制到 RAM
4. 把 `.bss` 清零
5. 调用 `main`
6. 如果 `main` 返回，就停在死循环

这些动作完成后，C 代码里的全局变量才处于可预期状态。

## 链接脚本负责什么？
链接脚本告诉链接器：

- Flash 从哪里开始，有多大
- RAM 从哪里开始，有多大
- 向量表放到哪里
- 代码和只读数据放到哪里
- 可写数据运行时放到哪里
- `.bss` 放到哪里
- 栈顶在哪里

当前 `STM32F401RE` 使用：

```text
FLASH: 0x08000000, 512K
RAM:   0x20000000, 96K
```

这些来自 ST 的 STM32F401xD/xE datasheet。

## firmware main 现在做什么？
当前 `firmware/src/main.c` 不初始化真实外设。它只做一个很小的自检：

- 创建默认告警配置
- 创建一组传感器样本
- 运行告警状态机
- 调用命令处理
- 调用响应格式
- 检查 BSP profile 和 RTOS task model 是否有效

这样做的意义是：固件 ELF 不是空壳，它已经链接并调用了现有核心逻辑。

## 为什么默认不构建 firmware？
默认开发仍然以主机测试为主：

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

固件构建需要交叉工具链和 toolchain 文件，所以通过开关显式启用：

```powershell
-D EW_BUILD_FIRMWARE=ON
```

这样不会影响日常主机测试。

## 当前还缺什么？
当前固件骨架还缺：

- STM32 HAL/LL
- 系统时钟配置
- GPIO/UART/I2C 初始化
- FreeRTOS 内核和任务创建
- 真实中断处理
- `.bin` / `.hex` 输出
- 烧录和板上验证

这些会在后续阶段逐步接入。
