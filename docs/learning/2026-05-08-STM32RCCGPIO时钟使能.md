# STM32 RCC GPIO 时钟使能

## 这一阶段在做什么？
前面已经有了两块 GPIO 相关能力：

```text
stm32_gpio_config  -> 配置 MODER/OTYPER/OSPEEDR/PUPDR
stm32_gpio_output  -> 写 BSRR 输出高/低电平
```

但在真实 STM32 上，GPIO 外设通常要先打开 RCC 时钟，否则后面对 GPIO 寄存器的访问不会按预期工作。这一阶段新增 `stm32_rcc_gpio_clock`，先把“打开某个 GPIO 端口时钟”这件事独立出来。

## 对应代码
- `drivers/include/embedded_workbench/stm32_rcc_gpio_clock.h`
- `drivers/src/stm32_rcc_gpio_clock.c`
- `tests/test_stm32_rcc_gpio_clock.c`
- `CMakeLists.txt`

## RCC 是什么？
`RCC` 可以理解成 STM32 的时钟控制模块。很多外设默认不工作，必须先打开它们的时钟。

对 GPIO 来说，常见流程是：

```text
打开 GPIOA 时钟
  -> 配置 PA5 为输出
  -> 写 GPIOA_BSRR 控制 PA5 高/低
```

如果少了第一步，后面配置和输出就没有可靠基础。

## 代码怎么读？
建议按这个顺序：

1. `stm32_rcc_gpio_clock.h`
   - 看 `stm32_rcc_gpio_clock_port_t`
   - 它把 `"PA"`、`"PB"` 这样的端口名绑定到 RCC enable register 的 bit
2. `stm32_rcc_gpio_clock.c`
   - 看 `find_port_clock`
   - 再看 `stm32_rcc_enable_gpio_port_clock`
   - 重点理解它只做 `enable_register |= 1 << bit`
3. `tests/test_stm32_rcc_gpio_clock.c`
   - 测试用普通变量模拟 RCC enable register
   - 验证重复开启是幂等的，不会清掉其他端口 bit

## 为什么不直接写死 PA/PB？
不同 STM32 系列和不同总线上的 RCC enable register 可能不一样。现在先用绑定表表达：

```text
"PA" -> bit 0
"PB" -> bit 1
```

这样主机测试可以不依赖真实芯片头文件，后续接真实板子时再把 `enable_register` 绑定到具体 RCC 地址。

## 和前两步怎么连？
目标板 GPIO 输出链路现在可以按这个顺序理解：

```text
stm32_rcc_enable_gpio_port_clock
  -> 打开 GPIO 端口时钟

stm32_gpio_configure_output
  -> 把 pin 配成输出模式

digital_output_write
  -> stm32_gpio_output
  -> 写 BSRR 输出高/低电平
```

这三步分别解决“外设有没有时钟”“pin 是不是输出模式”“当前输出高还是低”。

## 这一步还不能证明什么？
这一步还不能证明真实板上 GPIO 已经可用。它只证明：

- 端口名能匹配到 RCC bit
- enable register 会设置对应 bit
- 重复开启不会破坏已有 bit
- 未知端口和非法绑定会失败

真实板上还需要把 enable register 绑定到实际 RCC 地址，并做板上运行验证。

## 面试里怎么讲？
可以这样说：

> 我把 STM32 GPIO 输出链路拆成了 RCC 时钟、GPIO 配置、BSRR 输出三步，并分别做了主机测试。RCC 模块用端口名到 enable bit 的绑定表模拟真实寄存器，使得没有开发板时也能验证时钟使能逻辑的位操作。
