# FreeRTOS 任务模型

## 这一阶段在做什么？
这一阶段还没有引入真正的 FreeRTOS 内核源码，也没有调用 `xTaskCreate` 或 `xQueueCreate`。

我们先做的是任务模型描述：

- 未来系统有哪些任务
- 每个任务大概做什么
- 优先级和周期如何初步安排
- 任务之间通过哪些队列传数据

这样做的好处是，在接入真实 STM32 和 FreeRTOS 之前，先把系统并发结构想清楚。

## 第一版任务划分

`sensor_acquire`

采集任务。未来负责周期性读取传感器，把数据放入传感器样本队列。

`env_process`

处理任务。未来负责读取传感器样本，运行告警状态机，产生告警事件。

`communication`

通信任务。未来负责 UART 收发、命令解析、命令处理和响应输出。

`alarm_output`

告警输出任务。未来负责 LED、蜂鸣器、继电器等输出动作。

## 第一版队列划分

`sensor_sample_queue`

从采集任务到处理任务，传递 `sensor_sample_t`。

`command_queue`

从通信输入到命令处理，传递 `command_t`。

`response_queue`

从业务处理到通信输出，传递响应文本。

`alarm_event_queue`

从处理任务到告警输出任务，传递告警事件。

## 为什么先用队列？
FreeRTOS 中，队列常用于任务之间、任务和中断之间传递数据。官方参考手册也说明队列可用于任务间和任务/中断间的数据传递。

队列的一个重要特点是按值拷贝。FreeRTOS 官方教程说明，发送到队列的数据会被复制进队列，而不是默认只保存引用。这个模型对小结构体很适合，因为任务之间不需要争夺同一块内存的所有权。

本项目当前传递的数据都比较小：

- `sensor_sample_t`
- `command_t`
- 小型告警事件

所以第一版使用队列传值是合理的。后续如果出现很大的数据块，再考虑传指针或使用 stream/message buffer。

## 为什么现在不直接写 FreeRTOS 代码？
直接写 `xTaskCreate` 和 `xQueueCreate` 需要：

- FreeRTOS 源码
- FreeRTOSConfig.h
- 目标芯片启动文件
- 堆栈和中断配置
- 板级时钟和外设初始化

这些都和具体硬件强相关。当前项目的策略是先把可在主机上验证的逻辑做实，再接入目标板。

所以现在先把任务和队列作为普通 C 数据描述出来，并用测试保护它。

## 当前测试覆盖
当前测试覆盖：

- 任务模型整体合法
- 有 4 个任务
- 能查到处理任务及其优先级/周期
- 越界任务索引返回空
- 有 4 个队列
- 传感器样本队列的元素大小等于 `sizeof(sensor_sample_t)`
- 命令队列的元素大小等于 `sizeof(command_t)`
- 越界队列索引返回空
