# STM32 GPIO 初始化配置

## 这一阶段在做什么？
上一阶段已经能把高/低电平写到 STM32 `BSRR`。但真实 GPIO 要能正常输出，前面还需要把 pin 配成输出模式。

这一阶段新增 `stm32_gpio_config`，把 `board_pin_t` 描述的引脚映射到 STM32 GPIO 配置寄存器：

```text
board_pin_t("PA", 5)
  -> GPIOA registers
  -> MODER/OTYPER/OSPEEDR/PUPDR
```

## 对应代码
- `drivers/include/embedded_workbench/stm32_gpio_config.h`
- `drivers/src/stm32_gpio_config.c`
- `tests/test_stm32_gpio_config.c`
- `CMakeLists.txt`

## 这些寄存器分别管什么？
这一步只用到四类常见 STM32 GPIO 配置寄存器：

- `MODER`：选择 pin 模式，例如 input/output/alternate/analog
- `OTYPER`：选择推挽输出或开漏输出
- `OSPEEDR`：选择输出速度
- `PUPDR`：选择无上下拉、上拉或下拉

一个 pin 的 `MODER`、`OSPEEDR`、`PUPDR` 通常各占 2 bit；`OTYPER` 每个 pin 占 1 bit。

## 代码怎么读？
建议按这个顺序：

1. `stm32_gpio_config.h`
   - 先看 `stm32_gpio_registers_t`
   - 它不是完整 STM32 寄存器定义，只放当前需要配置的几个字段
2. `stm32_gpio_config.c`
   - 看 `write_two_bit_field`
   - 再看 `stm32_gpio_configure_output`
   - 重点理解“先清掉目标 pin 的位，再写入新值”
3. `tests/test_stm32_gpio_config.c`
   - 测试用 `0xffffffff` 和 `0` 两种初值，验证只改目标 pin，不误改其他位

## 为什么还不做 RCC？
GPIO 配置前通常要先打开端口时钟，也就是 RCC。当前先不做 RCC，是因为 RCC 更像板级启动流程的一部分：

- 不同 STM32 系列 RCC 寄存器位置和位定义可能不同
- 后续接 CMSIS/HAL 时会有更明确的芯片头文件
- 现在先把 GPIO pin 配置逻辑独立出来，便于主机测试

## 和 BSRR 输出后端怎么配合？
可以按这个顺序理解目标板输出链路：

```text
stm32_gpio_configure_output
  -> 把 pin 配成输出模式

digital_output_write
  -> stm32_gpio_output
  -> 写 BSRR 输出高/低电平
```

配置负责“这个引脚能不能作为输出用”，输出后端负责“现在让它高还是低”。

## 这一步还不能证明什么？
这一步仍然不能证明真实板上 LED 会亮。它只证明：

- 端口名能匹配到配置寄存器块
- pin 对应 bitfield 写法正确
- output type、speed、pull 能写入预期位置
- 错误参数不会修改寄存器

真实板上还需要 RCC、真实地址绑定和板上运行验证。

## 面试里怎么讲？
可以这样说：

> 我把 GPIO 输出拆成两个可验证步骤：先用 stm32_gpio_config 配置 MODER/OTYPER/OSPEEDR/PUPDR，再用 stm32_gpio_output 写 BSRR 控制电平。两个模块都可以在主机上用普通变量模拟寄存器做测试，后续接真实 STM32 地址时不需要改应用层逻辑。
