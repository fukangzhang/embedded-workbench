# 固件 USART2 初始化自检边界

## 决策

在 `firmware/src/main.c` 中加入 USART2 初始化链路自检，但继续使用模拟寄存器变量，不解引用真实 `RCC_APB1ENR` 或 `USART2` 地址。

## 职责

本阶段负责：

- 在固件入口中初始化 RCC/GPIO/USART 模拟寄存器。
- 通过 `stm32_board_usart2_init` 串起 GPIOA 时钟、PA2/PA3 AF7、USART2 时钟和 USART 8N1 配置。
- 检查 `AHB1ENR` bit0、`APB1ENR` bit17、GPIO alternate mode、AF7、USART `BRR/CR1`。
- 将检查结果纳入 `firmware_self_check`。

## 不负责

本阶段不负责：

- 在默认固件路径中解引用真实 USART2 寄存器地址。
- 真实串口收发。
- 串口中断、DMA 或 ring buffer。
- 将 USART2 字节流接到 `serial_command_service`。
- 板上 USB-UART 日志验证。

## 为什么这样分

USART bring-up 继续按两步推进：

1. 构建级自检：确认固件入口能链接并调用 USART2 初始化链路，寄存器位操作符合预期。
2. 板上验证：启用真实地址，下载到 NUCLEO-F401RE，通过 USB-UART 观察收发。

当前处在第一步。这样能在真实串口接入前，先把模块依赖、调用顺序和基本配置固定下来。

## 当前验证边界

固件构建能证明这段代码进入目标 ELF，也能在代码层面表达自检逻辑；但 CI 不会把 ELF 运行在 STM32 板上，所以它不是硬件行为验证。
