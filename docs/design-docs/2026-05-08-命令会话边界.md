# 命令会话边界

## 决策

新增 `command_session` 作为 app 层命令会话模块，统一处理“一行命令 -> 响应文本”。

## 职责

- 接收一行完整命令。
- 调用 `command_parser` 解析命令。
- 调用 `command_handler` 应用配置或识别请求。
- 调用 `response_format` 生成响应文本。
- 在配置改变后，用当前样本刷新告警状态。

## 不负责

本模块不负责：

- 字节流组帧，这属于 `serial_line`。
- UART/USART 寄存器访问。
- FreeRTOS queue 创建或调度。
- GPIO 输出。
- 持久化配置。

## 为什么这样分

通信接入会经历多层：

```text
UART byte stream
  -> serial_line
  -> command_session
  -> command_parser / command_handler / response_format
```

如果每个入口都自己拼这些调用顺序，`host_sim`、USART2 task 和测试会逐渐分叉。`command_session` 让命令响应行为集中在一个地方。

## 验证边界

`tests/test_command_session.c` 覆盖：

- 非法命令响应。
- `STATUS?` 响应。
- `CONFIG?` 响应。
- `SET` 成功后配置更新、状态刷新和响应拼接。
- 输出缓冲区不足。
- 空指针/非法参数防御。

它不覆盖真实串口收发、中断并发、DMA 或 FreeRTOS queue，这些属于后续通信接入任务。
