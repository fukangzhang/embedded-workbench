# 固件镜像产物边界

## 背景

前面固件构建主要生成 `embedded_firmware.elf`。ELF 适合调试和符号分析，但真实烧录工具通常还会需要 `.bin` 或 `.hex`。

## 决策

在 `embedded_firmware` 构建完成后自动生成：

- `embedded_firmware.bin`
- `embedded_firmware.hex`

生成方式使用 objcopy：

- GNU/ARM toolchain 使用 `-O ihex`。
- Zig objcopy 使用 `-O hex`。

工具选择顺序：

1. 如果显式传入 `EW_FIRMWARE_OBJCOPY`，使用这个工具。
2. 如果当前固件工具链发现了 `ZIG_EXE`，优先使用 `zig objcopy`。
3. 最后才使用 CMake 提供的 `CMAKE_OBJCOPY`。

这样做是为了避免 CI 或开发机上存在主机 `/usr/bin/objcopy` 时，误用主机工具去处理 Zig 生成的 ARM ELF。

## 边界

本阶段负责：

- 从 ELF 生成可烧录镜像文件。
- 让 CI 和本地固件构建覆盖镜像生成。
- 在 bring-up 文档中标明可用产物。

本阶段不负责：

- 调用 ST-LINK 或 OpenOCD 烧录。
- 自动探测开发板。
- 板上运行验证。
