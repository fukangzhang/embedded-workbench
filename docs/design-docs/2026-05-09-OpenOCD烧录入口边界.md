# OpenOCD 烧录入口边界

## 背景

固件构建已经能生成 `embedded_firmware.elf/.bin/.hex`。下一步需要一个清晰的入口，把这些产物交给真实烧录工具，但当前还不能假设开发机已经安装 OpenOCD，也不能假设板子已经连接。

## 决策

新增 `scripts/flash_nucleo_f401re_openocd.ps1`，作为 NUCLEO-F401RE 的 OpenOCD 烧录辅助脚本。

默认配置：

- interface：`interface/stlink.cfg`
- target：`target/stm32f4x.cfg`
- 默认镜像：`build-fw-real-usart2-command/embedded_firmware.elf`
- `.bin` 起始地址：`0x08000000`

脚本默认使用 OpenOCD 的 `program` helper，而不是手写底层 `flash write_image` 流程。OpenOCD 官方文档说明 `program` 会执行初始化、复位到可烧录状态、写入、可选校验、可选复位和退出。

## 边界

本阶段负责：

- 给出可 dry-run 的烧录命令入口。
- 让 `.elf/.hex/.bin` 三类固件产物都有明确使用方式。
- 在学习文档里解释为什么 `.bin` 需要 flash 起始地址。

本阶段不负责：

- 安装 OpenOCD。
- 自动识别开发板。
- 真实连接 ST-LINK 烧录。
- 证明固件已经在板上运行。

## 后续

真实上板后，应把烧录工具版本、固件提交、观察结果追加到 `hardware/nucleo-f401re-bringup.md` 的验证记录表。
