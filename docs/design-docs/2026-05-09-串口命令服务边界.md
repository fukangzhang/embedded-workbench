# 串口命令服务边界

## 背景

项目已经有两个独立模块：

- `serial_line`：只负责把逐字节输入组装成一行命令。
- `command_session`：只负责处理一行完整命令并生成响应文本。

真实 UART 接入时还需要一个中间层，把“收到一个 byte”转换成“必要时发送一段响应”。这个中间层就是 `serial_command_service`。

## 决策

新增 app 层模块 `serial_command_service`：

- 下游依赖 `serial_line`，处理逐字节输入、LF/CRLF 和溢出。
- 上游依赖 `command_session`，处理完整命令和应用状态。
- 通过调用者提供的 `write` callback 输出响应，不直接依赖 UART、stdio 或 GPIO。
- 所有 buffer 由调用者提供，避免在 MCU 固件中使用动态分配。
- `host_sim --script` 也走这个服务，用 `stdin` 模拟输入 byte，用 `stdout` 模拟发送响应。

## 边界

`serial_command_service` 负责：

- 维护串口行 reader。
- 在一行完成时调用 `command_session_handle_line`。
- 把响应文本交给 `write` callback。
- 把 idle、response sent、overflow、error 这些结果返回给调用者。

`serial_command_service` 不负责：

- 配置真实 USART 寄存器。
- 决定中断还是轮询。
- 管理 DMA。
- 解释命令语义。
- 控制 LED、蜂鸣器或执行器。

## 后续

真实 STM32 UART 接入时，UART 层只需要：

1. 初始化 USART 和 GPIO alternate function。
2. 收到 byte 时调用 `serial_command_service_feed`。
3. 在 `write` callback 中把响应逐字节发回 UART。
