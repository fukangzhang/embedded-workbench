# FreeRTOS 告警输出节拍边界

## 决策
FreeRTOS 告警输出 task 采用“事件更新状态 + 固定周期刷新输出”的方式：

- `alarm_event_queue` 只负责通知最新告警状态。
- `alarm_output_command_for_state` 把告警状态转成输出策略。
- `alarm_output_timing` 根据 `period_ms` 和 `elapsed_ms` 判断 indicator 当前应该亮还是灭。
- `alarm_output_sink` 负责应用已经渲染过的当前输出命令。

## 为什么这样分
告警状态变化和灯的闪烁节拍不是同一件事。状态变化来自传感器处理链路，闪烁节拍来自输出策略。把它们拆开后：

- 主机侧可以继续单独测试 `alarm_output_timing`。
- FreeRTOS 侧只负责按固定频率刷新当前输出。
- 后续接真实 GPIO/HAL 时，不需要改告警状态机。

## 当前边界
当前刷新间隔固定为 50ms，作为早期构建级骨架的一部分。它不是最终产品参数，也还没有板上运行验证。

真实硬件验证需要后续补齐：

- STM32 GPIO 后端。
- 板上 LED/蜂鸣器/执行器连接确认。
- 实机观察 indicator 是否按 `period_ms` 闪烁。

## 不做什么
本阶段不把 `alarm_output_timing` 写进驱动层，也不让 `digital_output` 理解告警状态。驱动层只处理“某个数字输出通道开/关”，应用层负责决定什么时候开/关。
