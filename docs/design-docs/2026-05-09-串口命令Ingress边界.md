# 串口命令 Ingress 边界

## 背景

裸机 USART2 命令 loop 可以使用 `serial_command_service`，因为它收到一行后可以同步处理并写回响应。

FreeRTOS 路径不同：串口输入应该先进入 `command_queue`，再由 `communication_task` 处理命令和响应。为此需要一个只负责输入转换的模块。

## 决策

新增 `serial_command_ingress`：

```text
serial byte
  -> serial_line
  -> command_parser
  -> submit(command_t)
```

## 边界

- 本模块不修改 `alarm_config_t`、`alarm_state_t` 或 `sensor_sample_t`。
- 本模块不生成响应文本。
- 本模块不直接依赖 FreeRTOS API，只通过 submit callback 把 `command_t` 交给下一跳。
- 解析失败时提交 `COMMAND_TYPE_INVALID`，由后续响应层统一产生错误响应。
- 行缓冲仍复用 `serial_line`，避免两套 CR/LF 和 overflow 行为。

## 不做什么

- 不替换已有 `serial_command_service`。
- 不直接接 USART2 寄存器。
- 不创建 FreeRTOS task。

## 后续

下一步可以在固件 FreeRTOS 路径中把 `serial_command_ingress` 的 submit callback 接到 `command_queue`，再通过 USART2 reader 周期性 feed 字节。
