# STM32 USART 串口 IO 适配器边界

## 背景

`stm32_usart` 已经能读写单个 USART 字节，`serial_command_service` 已经能通过 writer callback 输出响应。但两者之间还缺一层小适配：把 USART 寄存器 helper 包成上层可以传入的 I/O 回调。

## 决策

新增 `stm32_usart_serial_io`：

- `stm32_usart_serial_io_read_byte`：非阻塞读一个字节。
- `stm32_usart_serial_io_write`：按 buffer 写出多个字节，签名兼容 `serial_command_service_write_fn`。
- `stm32_usart_serial_io_context_t`：保存 USART 寄存器指针和 TXE 最大轮询次数。

写路径使用有限轮询，而不是无限等待。这样真实硬件异常或 USART 没初始化时，调用者可以得到失败结果，不会永久卡住。

## 边界

本模块负责：

- 把 `void *context` 转回 USART I/O context。
- 调用 `stm32_usart_read_byte` 和 `stm32_usart_write_byte`。
- 为写 buffer 提供 TXE 有限轮询。
- 提供能直接给 `serial_command_service` 使用的 writer 函数。

本模块不负责：

- 初始化 USART2。
- 管理 ring buffer。
- 中断或 DMA 收发。
- 串口命令解析。
- 把它接入 `firmware/src/main.c`。

## 后续

下一步可以在固件里建立 USART2 command loop 雏形：

```text
USART2 RX byte
  -> stm32_usart_serial_io_read_byte
  -> serial_command_service_feed
  -> stm32_usart_serial_io_write
```

这一步仍应先通过模拟寄存器或受控编译开关验证，再进入真实板卡串口收发。
