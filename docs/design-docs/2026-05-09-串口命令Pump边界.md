# 串口命令 Pump 边界

## 背景

`serial_command_service` 已经能处理单个 byte，但真实固件通常需要一个循环：不断从串口 reader 取出可用字节，再喂给 service。这个循环如果直接写进 `firmware/main.c`，后续换成 FreeRTOS task 或主机测试会不方便。

## 决策

新增 `serial_command_pump` 作为应用层胶水：

```text
reader callback
  -> serial_command_pump_poll
  -> serial_command_service_feed
  -> writer callback
```

`serial_command_pump_poll` 是有界的：每次最多处理 `max_bytes` 个字节，并在收到响应、overflow、error 或 reader 暂时无数据时返回。

## 边界

本模块负责：

- 调用非阻塞 reader callback。
- 把读到的 byte 喂给 `serial_command_service_feed`。
- 限制每轮处理的最大字节数。
- 把 service status 返回给调用者。

本模块不负责：

- 知道 USART、USB CDC 或 stdin 的具体实现。
- 初始化 `serial_command_service`。
- 分配 buffer。
- 调度 FreeRTOS task。
- 实现中断、DMA 或 ring buffer。

## 后续

下一步可以在固件里把它接到 `stm32_usart_serial_io_read_byte`：

```text
stm32_usart_serial_io_read_byte
  -> serial_command_pump_poll
  -> serial_command_service_feed
  -> stm32_usart_serial_io_write
```

这样真实 USART2 polling loop 会变得很薄，主要负责调用 pump，而不是重新写一套命令处理逻辑。
