# 固件 USART2 命令服务自检边界

## 背景

现在项目已经有三块能力：

- `serial_command_service` 能处理逐字节输入并生成响应。
- `stm32_usart_serial_io` 能把响应 buffer 写到 USART 寄存器 helper。
- `firmware/src/main.c` 已经有 USART2 初始化自检。

还缺一个固件侧集成自检，证明命令服务能把响应通过 USART2 I/O 适配器写出去。

## 决策

在 `firmware/src/main.c` 中新增 `firmware_usart2_command_service_self_check`：

```text
STATUS?\n
  -> serial_command_service_feed
  -> command_session
  -> response_format
  -> stm32_usart_serial_io_write
  -> fake USART2 DR
```

自检仍然使用模拟 USART2 寄存器，并手动置位 TXE，让 writer 可以完成发送。

## 边界

本阶段负责：

- 在固件入口中初始化 `serial_command_service`。
- 使用 `stm32_usart_serial_io_write` 作为 writer callback。
- 喂入一条 `STATUS?\n` 命令。
- 检查响应以 `OK` 开头，并且最后一个写入 USART2 `DR` 的字节是换行。
- 将检查结果纳入 `firmware_self_check`。

本阶段不负责：

- 真实 USART2 RX 轮询循环。
- 从真实 `DR` 读入外部串口字节。
- 长时间运行的命令任务。
- 中断、DMA、ring buffer。
- USB-UART 终端实测。

## 后续

下一步可以做一个受编译开关保护的固件 USART2 command polling loop。那一步才会把真实 `RXNE/DR` 输入接到 `serial_command_service_feed`。
