# 滤波传感器来源边界

## 背景

`sensor_sample_filter` 已经提供独立滤波算法，但它还没有接到任何传感器读取链路上。直接修改 `sensor_acquisition` 会改变所有运行路径的默认行为，也会让“是否滤波”变成采集模块的内置策略。

## 决策

新增 `filtered_sensor_source` driver 模块，把任意合法 `sensor_source_t` 包装成一个新的 `sensor_source_t`：

```text
inner sensor_source_t
  -> sensor_sample_filter
  -> outer sensor_source_t
```

初始化时复制 `sensor_source_t` 小接口本身，保留其 `context` 指针。调用者仍负责保证 `context` 指向的序列、fake 或真实硬件状态在 wrapper 使用期间有效。

## 边界

本阶段负责：

- 定义 `filtered_sensor_source_t`。
- 复用 `sensor_source_read` 做内层 source 校验。
- 复用 `sensor_sample_filter_apply` 做滤波。
- 提供 reset，使下一帧重新成为滤波初始值。
- 用主机测试覆盖首帧透传、后续平滑、失败传播和参数校验。

本阶段不负责：

- 默认接入 `host_sim`、FreeRTOS 或固件入口。
- 决定真实传感器型号。
- 决定产品级滤波参数。
- 增加串口命令来调整滤波参数。

## 后续

- 真实传感器 source 出现后，可以优先在 `firmware/src/main.c` 或 FreeRTOS context 装配处选择是否包上滤波层。
- 如果后续需要运行期配置，可以把 alpha 参数纳入配置更新链路，但那应该单独设计配置一致性和 reset 时机。
