# SAMPLE 命令边界

## 背景

当前固件和 `host_sim` 已经能通过串口命令查询状态、查询配置、修改阈值。但真实传感器还没有接入，板上或主机演示时只能看到固定 sample，无法主动触发 warning/alarm/recovery 路径。

## 决策

新增文本命令：

```text
SAMPLE <temp_c_x10> <humidity_rh_x10> <light_lux> <smoke_ppm>
```

示例：

```text
SAMPLE 360 600 250 20
```

执行成功后：

1. `command_parser` 只负责把 4 个整数读进 `command_t`。
2. `command_handler` 用现有 `sensor_sample_is_valid` 校验范围。
3. 校验通过才写回当前 `sensor_sample_t`。
4. `command_session` 重新计算 `alarm_state`。
5. 响应 `OK` 和最新 `STATUS`。

## 边界

本阶段负责：

- 给 host/串口演示提供可控 sample 输入。
- 复用现有传感器样本范围规则。
- 覆盖 parser、handler、session、serial service 和 host script 测试。

本阶段不负责：

- 接真实传感器芯片。
- 设计传感器采集任务。
- 把 sample 持久化。
- 做二进制通信协议或 telemetry 帧。

## 为什么不是 SENSOR?

这里命令名选 `SAMPLE`，强调它注入的是“一帧采样值”，不是配置传感器硬件本身。后续真实传感器驱动接入后，这条命令仍可作为调试覆盖入口保留。
