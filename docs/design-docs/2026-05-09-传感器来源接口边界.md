# 传感器来源接口边界

## 背景

项目已经有 `sensor_sample_t` 数据模型，也有 `SAMPLE` 命令可以手工注入样本。但后续真实传感器接入不能直接把 I2C/ADC 读取逻辑塞进告警状态机或 FreeRTOS 处理任务里，否则测试和移植都会变乱。

## 决策

新增 `sensor_source_t`：

```c
typedef bool (*sensor_source_read_fn)(void *context, sensor_sample_t *sample_out);

typedef struct {
    sensor_source_read_fn read;
    void *context;
} sensor_source_t;
```

`sensor_source_read` 统一负责：

1. 检查 source 和输出指针。
2. 调用具体来源的 read callback。
3. 用 `sensor_sample_is_valid` 校验读出的 sample。

FreeRTOS `sensor_acquire_task` 现在会在 `freertos_rtos_port_context_t.sensor_source` 非空且读样本成功时，把 sample 发送到 `sensor_sample_queue`。

## 边界

本阶段负责：

- 定义传感器输入来源接口。
- 在主机测试里用 fake source 验证读取、失败和非法 sample。
- 让 FreeRTOS 采集任务具备从 source 到 queue 的最小数据流。

本阶段不负责：

- 实现真实 I2C/SPI/ADC 传感器驱动。
- 选择具体传感器型号。
- 在板上启动 FreeRTOS 调度器并观察任务运行。
- 替代 `SAMPLE` 命令；`SAMPLE` 仍然是调试/演示入口。

## 后续

下一步可以添加一个模拟传感器 source，或选择一个真实传感器芯片实现 `sensor_source_t`，再把它挂到 `firmware/src/main.c` 的 FreeRTOS context 中。
