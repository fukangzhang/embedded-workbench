# 主机仿真优先策略

## 背景
项目目标是做一个适合求职展示的嵌入式项目，但当前阶段不应被具体开发板、传感器型号或厂商 SDK 绑定。

## 决策
项目先采用主机仿真优先路线。

优先在主机上完成：
- 传感器数据结构
- 告警状态机
- 配置参数
- 串口风格命令解析
- 自动化测试

后续再接入：
- STM32 BSP
- FreeRTOS 任务
- UART/I2C/SPI 驱动
- 真实传感器和执行器

## 原因
- 初期没有真实硬件也能持续推进
- 纯逻辑模块更容易写测试
- 更容易解释模块边界和设计思路
- 后续移植到目标板时，只替换底层接口，不重写核心逻辑

## 影响
- `drivers/` 需要保留硬件无关接口
- `app/` 不直接依赖厂商 SDK
- `tests/` 会先成为项目质量的主要验证入口
- `bsp/` 初期可以为空或只放接口占位，等目标板确定后再填充
