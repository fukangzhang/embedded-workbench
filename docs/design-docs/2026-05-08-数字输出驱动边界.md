# 数字输出驱动边界

## Context
项目已经有 board profile 记录告警 LED、蜂鸣器和执行器引脚，也有 `alarm_output_sink` 表达应用层输出目标。

在接入真实 STM32 GPIO 前，需要一个可测试的小驱动边界，避免应用层直接操作具体端口和引脚。

## Decision
新增 `drivers/digital_output`，它依赖 BSP 的 `board_pin_t`，但不依赖 `app`。

接口只表达三件事：

- 目标引脚
- 输出电平
- 写入回调

## Consequences
- `drivers` 明确依赖 `bsp`，符合当前分层规则。
- 应用层可以在后续通过适配器把告警输出转换成数字输出。
- 当前实现仍是回调抽象，不绑定 HAL 或寄存器。
- 真实硬件失败重试、GPIO 初始化和输出节拍调度留到后续任务。
